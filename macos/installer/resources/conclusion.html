Instalado — mas ainda não ativo.

O daemon está rodando e o módulo PAM está em /usr/local/lib/pam. Faltam dois passos, nesta ordem.

1. Pareie o celular

sudo phoneauthctl pair

Um QR code aparece no terminal. Escaneie com o app PhoneAuth e confirme que o número mostrado no Mac é o mesmo do celular.

2. Só depois de parear, plugue o módulo no sudo

Crie ou edite /etc/pam.d/sudo_local e ponha esta linha antes das outras:

auth  sufficient  /usr/local/lib/pam/pam_phoneauth.so  timeout=30

sudo_local é um drop-in que sobrevive a atualizações do macOS. Editar /etc/pam.d/sudo direto seria desfeito no próximo update.

Antes de fechar o terminal que você usou.
Abra outra janela e rode sudo true. Confirme que funciona. Se algo der errado, a primeira janela ainda tem sudo válido e conserta com sudo rm /etc/pam.d/sudo_local.
O módulo entra como sufficient, jamais required. Daemon fora do ar, celular sem bateria ou bug no código fazem o macOS simplesmente voltar a pedir a senha — ele nunca tranca você fora da máquina. Um erro de digitação no sudo_local, porém, é outra história: daí a janela reserva acima.

O que isto não cobre

Não desbloqueia o FileVault no boot (ali ainda não existe rede nem daemon) e não cobre os diálogos gráficos do SecurityAgent — só a pilha PAM, como sudo e su. O celular precisa estar na mesma rede local.

Para desinstalar

sudo rm /etc/pam.d/sudo_local
sudo launchctl bootout system/dev.phoneauth.daemon
sudo rm /usr/local/bin/phoneauth{d,ctl}
sudo rm /usr/local/lib/pam/pam_phoneauth.so
sudo rm /Library/LaunchDaemons/dev.phoneauth.daemon.plist
sudo rm -rf "/Library/Application Support/PhoneAuth"
